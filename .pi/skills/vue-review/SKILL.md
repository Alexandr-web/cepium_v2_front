# Код-ревью

1. Получи изменения: `git diff` (или `git diff main...HEAD`).
2. Для каждого файла проверь по чек-листу:
   - Типобезопасность: any, небезопасные приведения, непокрытые null/undefined.
   - Реактивность: потеря реактивности, лишние watch, утечки подписок.
   - SSR: доступ к window/document вне onMounted, гидрационные расхождения.
   - Производительность: лишние перерисовки, тяжелые computed, отсутствие lazy-загрузки.
   - Доступность и семантика верстки.
   - Безопасность: v-html, XSS, секреты на клиенте (runtimeConfig.public).
   - Тесты и читаемость.
3. Запусти typecheck и lint.
4. Формат ответа: сначала критичное (блокеры), потом важное, потом мелочи.
   К каждому замечанию: файл:строка, проблема, почему это плохо, как исправить.
5. Ничего не правь без явной просьбы, ревью только читает.
